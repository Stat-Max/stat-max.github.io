Git 사용설명서

1. Git이란?

Git은 파일 변경 이력을 관리하고 여러 사람이 함께 작업할 수 있게 도와주는 분산 버전 관리 시스템입니다. 소스코드, 문서, 설정 파일 등을 안전하게 저장하고, 이전 버전으로 복구하거나 협업을 쉽게 할 수 있습니다.

Git은 “코드 저장소”를 관리하는 도구라 생각하면 됩니다. 마치 프로젝트의 시간 여행 기록장과 같습니다.

2. 왜 Git을 사용하나?

  • 수정 기록을 남길 수 있음
  • 이전 버전으로 되돌릴 수 있음
  • 여러 사람이 동시에 작업할 수 있음
  • 브랜치를 통해 기능별 개발이 가능함
  • GitHub 같은 원격 저장소와 연동 가능

3. Git 기본 용어

  • Repository: 저장소, 프로젝트의 파일과 기록이 있는 공간
  • Commit: 변경 내용을 저장하는 단위
  • Branch: 독립적인 작업 흐름
  • Merge: 브랜치 내용을 합치는 작업
  • Clone: 원격 저장소를 로컬로 복사
  • Push: 로컬 변경 내용을 원격 저장소로 올림
  • Pull: 원격 저장소의 변경을 로컬로 가져옴

4. 설치 및 초기 설정

Git 설치

Windows는 Git for Windows를 설치하고, macOS는 Homebrew로 설치할 수 있습니다.

git --version

설치 후 버전이 출력되면 정상입니다.

사용자 정보 설정

git config --global user.name "홍길동" git config --global user.email "hong@example.com"

설정 확인

git config --list

5. 저장소 만들기

새 프로젝트 초기화

mkdir myproject cd myproject git init

이 명령을 실행하면 .git 폴더가 생성되고, Git이 이 폴더를 관리하기 시작합니다.

상태 확인

git status

현재 어떤 파일이 수정되었는지, 새 파일이 추가되었는지 확인할 수 있습니다.

6. 파일 추가와 커밋

파일 추가

git add index.html

특정 파일을 스테이징 영역에 올리는 명령입니다.

모든 파일 추가

git add .

커밋 생성

git commit -m "첫 번째 커밋"

커밋은 변경 사항을 기록하는 ‘스냅샷’이라고 생각하면 됩니다.

커밋 메시지는 “무엇을 바꿨는지” 한눈에 알 수 있게 짧고 명확하게 작성하는 것이 좋습니다.

7. 브랜치 사용

브랜치 목록 보기

git branch

새 브랜치 만들기

git branch feature/login

브랜치 이동

git checkout feature/login

브랜치 생성과 이동을 한 번에

git checkout -b feature/login

브랜치 병합

git checkout main git merge feature/login

기능 개발이 끝났으면 메인 브랜치에 합칩니다.

8. 원격 저장소와 연결

원격 저장소 추가

git remote add origin https://github.com/username/repository.git

원격 저장소 확인

git remote -v

원격 저장소에 업로드

git push -u origin main

처음 업로드할 때는 -u 옵션을 사용하면 이후 편하게 push가 가능합니다.

원격 저장소 갱신

git pull origin main

9. GitHub에서 작업하기

GitHub는 Git 저장소를 온라인으로 공유하고 협업을 돕는 서비스입니다.

  1. GitHub에서 새 저장소 생성
  2. 로컬 저장소와 연결
  3. 커밋 후 push
  4. Pull Request로 코드 리뷰
  5. main 브랜치에 병합
팀 프로젝트에서는 작업 전에 항상 pull을 하고, 브랜치를 나눠서 개발하는 습관이 중요합니다.

10. 자주 쓰는 Git 명령 요약

git init git status git add . git commit -m "메시지" git branch git checkout -b feature/test git merge feature/test git remote add origin URL git push -u origin main git pull origin main git log

11. 실전 워크플로우

git checkout -b feature/login # 기능 구현 git add . git commit -m "로그인 기능 추가" git push -u origin feature/login # GitHub에서 Pull Request 생성 # 리뷰 후 main 브랜치에 merge

이 흐름은 일반적인 협업 개발 방식입니다.

12. Git 사용 팁

  • 작업 전에 git status를 자주 확인하세요.
  • 커밋 메시지는 “왜 변경했는지”를 들어내는 내용으로 작성하세요.
  • 중요한 작업은 브랜치를 분리해서 실험하세요.
  • 실수했을 때는 git log와 git checkout으로 복구할 수 있습니다.
  • 프로젝트마다 .gitignore를 설정해 불필요한 파일을 추적하지 않게 하세요.

13. 한 번에 이해하는 Git 그래픽

1) 작업 → 스테이징 → 커밋

작업 폴더
↓
git add
↓
git commit

코드를 수정한 뒤, 추가하고 기록으로 남기는 과정입니다. 이 단계가 있어야 변경 내용을 안전하게 저장할 수 있습니다.

2) 브랜치로 분기

main
→
feature/login

브랜치는 프로젝트의 독립적인 작업선입니다. 메인 코드에 영향 주지 않고 기능을 실험하거나 개발할 수 있습니다.

3) 원격 저장소 동기화

내 컴퓨터
⇄
GitHub

push는 로컬 변경을 서버로 올리고, pull은 서버의 변경을 내 컴퓨터로 가져옵니다. 협업의 핵심입니다.

4) 병합(merge)

feature 작업
＋
main

기능 개발이 끝나면 브랜치 내용을 main에 합칩니다. 이때 완성된 결과가 프로젝트에 반영됩니다.

작업 저장 준비 단계 완료 기록

14. 마무리

Git은 단순한 저장 도구가 아니라 협업과 버전 관리의 핵심 도구입니다. 초반엔 명령이 어렵게 느껴질 수 있지만, 자주 쓰다 보면 기본 흐름이 자연스럽게 익숙해집니다.

가장 중요한 것은 작게 나누어 커밋하고, 브랜치를 활용하며, 정기적으로 push/pull하는 습관입니다.
